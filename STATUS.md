## Changes from earlier reports you should know about
- **Curly-apostrophe scorer bug.** It also affected `REPORT_2026-11-06_one_neuron_gates.md`. The system prompt
  doesn't halve entity fabrication: it cuts it to ~7%, but makes Gemma deny knowing 2/3 of real entities (facts kept
  57% → 20%).
- **Gate numbers under the standard scorer.** The old report's "98% → 2%" used a re-scored "outright fabrication"
  metric. With the standard scorer (no abstention in the first 400 characters), the gate gives 98% → 15.5%.
- **Two framework fixes along the way.**
  - A label-free calibration set, so the gate's threshold doesn't depend on tiny practice sets.
  - `Task.failed()`, which keeps a gate from suppressing a model's own correct openers. This bit on Qwen.

## Open items / caveats
- **Sweep coverage.** agent_injection has 2 seeds. The signoff sweep uses a 64-prompt held-out subset. The langmix
  sweep wasn't run: one fit plus eval takes about 25 minutes.
- **Varied-phrasing bigdata runs** (`results/entity/bigdata/*_xv*.json`) were rebuilt from the run log. The raw
  outputs are still on the stopped L4 box (`wm-syco`, eu-central-1a, `~/wp/results/entity/bigdata/`).
- **Gate threshold rule.** "Above every ordinary practice position" gets stricter as practice data grows, which hurts
  the signoff gate at large n. A quantile rule would probably fix it; not tried.
- **Langmix.** The one-neuron template doesn't fit this failure. The agents' earlier edit (`gate_recipe`) does.
- **Blind agent session s1** lost ~70 minutes to a double-booked GPU. s2 ran clean.
- **AWS.** All three `wm-*` instances are **stopped**, not terminated; their EBS volumes still bill.
